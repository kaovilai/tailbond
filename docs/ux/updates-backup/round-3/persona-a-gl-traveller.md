# Round 3: persona A, "GL traveller"

A consultant who travels monthly with a GL.iNet Slate 7 and an Android phone, knows GL's admin panel but isn't a network engineer, and had a relative set up the Fedora home server.

Screens used: glinet r01, r02, r03, r04, r05, r06, r07, r10, r13, s01; web w01, w02, w05, w06 (desktop and phone), w07, w10, w11, w12; android 01, 03, 10, 11, 30, 37.

## Task 1: Make sure everything stays up to date

**Done?** Partly. I can read each device's version (router panel, phone Updates page, home server dashboard with its device list) and see that slate7 and pixel-8 are out of date. I can update the router and the phone myself. I can't update the Fedora home server without a terminal. Screens: w01, w02, s01, r01, r02, r03, r04, r05, r07, android 01, 03, 10, 11.

**Findings**

- **medium**, w01-homebox-dnf-update-available-desktop.png: The only way to update the home server is `sudo dnf upgrade tailbond-server` in a terminal, and turning on automatic installs means editing `/etc/dnf/automatic.conf`. I can't do either. "By whoever looks after it" doesn't help me hand the job over. Suggestion: add a "Send these steps to whoever looks after this computer" action (copy or share a short plain message), and say clearly whether this machine updates itself today (yes/no), not how dnf-automatic is configured.
- **medium**, w01-homebox-dnf-update-available-desktop.png / s01-flint-devices-out-of-date-desktop.png: Orange "Out of date" chips on slate7 and pixel-8 suggest urgency, but nothing says whether a 0.1.0 router still works with a 0.2.x home server, or whether the order matters (server first or router first). Mid-trip I can't tell if I must act now. Suggestion: add one line per device, such as "Works with this server; update when convenient" or "Must update to keep connecting", and say which side to update first.
- **medium**, r05-router-automatic-desktop.png: Automatic installs "between 03:00 and 05:00 (this router's time)". On a router that changes time zones every month, I don't know what "this router's time" is. It also doesn't say what happens if the router is off overnight (packed in a bag): does it install mid-afternoon during a call? Suggestion: show the router's current time and the next window ("next possible install: tonight 03:00 hotel time, if the router is on"), and promise it never installs outside the window.
- **low**, w01-homebox-dnf-update-available-desktop.png: The tab badge shows "3" (and "2" in w02) with no hint of what's being counted (one update plus two devices?). Suggestion: make the badge a dot, or give it a tooltip such as "1 update, 2 devices out of date".
- **low**, w01-homebox-dnf-update-available-desktop.png: The card says 0.2.1 is available, but also "a new version reaches dnf shortly after the release". If dnf answers "Nothing to do", I'll think the update is broken. Suggestion: say "If dnf says nothing to do, try again in a few hours", or show "Available in dnf: yes/not yet".
- **low**, r02-router-update-available-desktop.png / r01-router-up-to-date-desktop.png / android 11-updates-available.png: The same version appears as "0.2.0" (card), "0.2.0-r1" and "0.1.0-r42" (router footer), and "v0.2.0" (Android). Suggestion: use one format everywhere, with the build suffix only in a details view.
- **low**, r03-router-installing-desktop.png: While the router says "Installing… tailbond restarts", the top card still shows "Connected to homebox" with live speeds. I can't tell if my call is about to drop. Suggestion: during install, have the top card say "Restarting for update, back in about a minute".
- **low**, r04-router-rolled-back-desktop.png: The policy is Tell me, yet the note explains what Automatic will do. It also doesn't say whether I should do anything (report it, wait), or whether "Try 0.2.0 again" might cut the internet for up to 60 s again with the kill switch on. Suggestion: drop the Automatic sentence when the policy isn't Automatic, add "Nothing to do", and warn under "Try 0.2.0 again" that it may drop devices for up to a minute.
- **low**, android 11-updates-available.png: "Android asks to allow your browser to install apps; that's normal". A consultant's work phone may be managed and block this, and there's no alternative given. Suggestion: add "If your phone doesn't allow this, use Obtainium or ask your IT", and say to turn the browser's permission off again afterwards.

## Task 2: Move the home server to a new machine using a backup

**Done?** Partly. Making the backup is clear (w05). Every restore screen shows a VPS moving to a new IP; none shows a Fedora PC replaced at home. The "Before you restore" steps need a terminal and the Tailscale admin console, and they leave me guessing what my travel router needs. Screens: w02, w05, w06 (desktop and phone), w07, w10, w11, w12, s01, r01, r13, android 30, 37.

**Findings**

- **high**, w06-restore-preview-new-vps-desktop.png / w07-restore-done-desktop.png: Step 2 says "a travel router with the kill switch on has no internet until it reconnects, so send it its new link", and points to "Devices tab, the QR button". A router can't scan a QR code, and the router panel (r01) has no field for a new link, only "Ask to connect again" and "Unpair". If my relative does the move while I'm abroad, my Slate 7 drops all hotel internet and I have no way to get it back. Suggestion: name what each router needs ("slate7: not on Tailscale, needs a new link") and give a router-friendly way to deliver it (a pasteable code for the router's tailbond panel, or keep the old address working until every device has moved). Also say plainly: "Don't do this while a travel router is away, or turn its kill switch off first".
- **medium**, w06-restore-preview-new-vps-desktop.png: The Backup card promises "the restore preview says what each device needs", but the preview just says "check slate7, pixel-8, beryl". pixel-8 shows up as a Tailscale machine in r01, so I can't tell if it's a "device with Tailscale" or one that "needs its link again". Suggestion: list each device with its own result, such as "pixel-8: reconnects by itself" or "slate7: needs a new link".
- **medium**, w06-restore-preview-new-vps-desktop.png / w12-whats-inside-desktop.png: My case is a new Fedora PC at home, behind `home.example.net`. w12 lists "Public address home.example.net" as part of the backup, but w06 says the restore keeps "this machine's" address. I can't tell whether devices will still reach `home.example.net`. Nothing mentions moving the home router's port forward (UDP 443) to the new PC, and firewall settings are "not included". Suggestion: show the same-home preview ("Devices reach home.example.net:443; point your home router's port forward to this PC; open UDP 443 in its firewall"), and state which address the new machine ends up with.
- **medium**, w06-restore-preview-new-vps-desktop.png: Step 1 is a terminal command (`sudo systemctl disable --now tailbond`). It has no Copy button and wraps across lines at "--". Steps 2 and 3 send me into the Tailscale admin console to remove or rename machines and approve 10.83.142.0/24, with no link. Suggestion: give the old machine's dashboard a "Retire this server" button that does step 1. Add Copy to every command, a link to the Tailscale console page, and the exact names to type.
- **medium**, w07-restore-done-desktop.png: After the restore, the dialog says "If you haven't already: Before restoring, turn tailbond off on vps". At that point the new machine is already live, so if both are running, devices are already switching back and forth. "Send it its new link before you switch over" is too late too. The checklist disappears on Done, and the red Restore button in w06 doesn't make me confirm the old machine is off. Suggestion: in w06, require a tick ("The old server is off") before Restore is enabled. In w07, rewrite in the present ("Turn the old server off now; until then…"), and keep the checklist as a banner until each item is done.
- **low**, w05-backup-download-dialog-desktop.png / w11-scheduled-backups-change-desktop.png: Manual backups and automatic backups each have their own passphrase, and the automatic one is never shown again. At restore time I won't know which passphrase a saved file needs. Suggestion: in the Saved backups list, label each file "manual passphrase" or "automatic-backup passphrase".
- **low**, android 37-restore-a-server-backup.png: Refusing a server backup is shown in error red, and "Restore it there" doesn't say where or how. Suggestion: use neutral styling, and say "Open homebox's tailbond page → Updates & backup → Restore from a backup".

## Task 3: The router got a GL firmware update. Is tailbond still there?

**Done?** Yes. The top card says "tailbond is back after the firmware update, with your settings" and the Updates card says "Nothing to do". The kill switch still shows On. Screens: r06, r01, r13, s01.

**Findings**

- **medium**, r06-router-reinstalled-after-firmware-upgrade-desktop.png: Nothing says what happened to my devices' traffic between the firmware reboot and the reinstall at 21:36. tailbond (and its kill switch) was missing for that time, so work traffic may have gone out over the hotel Wi-Fi unprotected. Suggestion: say it outright, such as "From 21:31 to 21:36 devices here were blocked" or "were not protected by tailbond", and if traffic could leak, recommend turning Wi-Fi off before a firmware upgrade.
- **medium**, r06-router-reinstalled-after-firmware-upgrade-desktop.png / r01-router-up-to-date-desktop.png: The "Keep Settings" warning only shows after an upgrade that already worked. In the failure case (no Keep Settings), tailbond and this page are gone, so I never see the recovery text. "Install tailbond again" doesn't say where the package comes from: it's on homebox's page (s01), which I'd need to reach from the road, then upload through LuCI. Suggestion: put a short "Before a GL firmware upgrade: keep 'Keep Settings' ticked" note in the Backup card. Add a one-page offline recovery note, downloadable with the backup, that says where to get the router package, the LuCI steps, and which passphrase the router's backups use.
- **medium**, r13-router-whats-inside-desktop.png: The recovery steps say "On a new router: install tailbond, sign in to Tailscale, then restore". But r01 says this router reaches the tailnet "through the bond to homebox (not this router's own Tailscale)". I don't know if I have to sign the router in to Tailscale. Suggestion: write the steps for the travel-router role, without the Tailscale sign-in, or say when it applies.
- **low**, r06-router-reinstalled-after-firmware-upgrade-desktop.png: "From the copy kept on this router (or, if that was gone, from the GitHub release)" doesn't say which one actually happened. That matters, because the GitHub route could have brought a different version. Suggestion: state the source used, plus "same version as before" or "now on X".
- **low**, r06-router-reinstalled-after-firmware-upgrade-desktop.png: The top card shows "Up 2 h 13 min" to homebox, but tailbond reinstalled itself at 21:36, 24 minutes ago. That makes me doubt either message. Suggestion: reset the uptime after a reinstall, or say "connected since 21:37".
