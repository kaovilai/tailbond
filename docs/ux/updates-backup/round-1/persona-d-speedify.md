Persona: years on Speedify (silent app-store updates) and Peplink/SpeedFusion at work (scheduled firmware, config backup/restore files); expects a clear version, one-click backup, a restore that just works on new hardware, and counts every extra step.

Screens used:

- Web dashboard: w01, w02, w03, w04, w05, w06, w07, w08, w09, w10, w11, w12, w13 (desktop)
- Android: 01, 02, 10, 11, 12, 19, 30, 31b, 34, 37

Phone variants of the GL and web screens were skipped after the desktop versions.

## Task 1: Make sure everything stays up to date

**Done?** Partly. I can read the version for each device: router r01/r02, home server w01/w02/s01, phone 01/02/10/11. But only the VPS and the routers update with one click. The Fedora home server needs a terminal, and the phone needs a browser sideload or a third-party app. I also can't always tell whether a device is behind. Screens: r01, r02, r03, r04, r05, r07, s01, w01, w02, w03, w04, w08, w09, w13, 01, 02, 10, 11, 12, 19.

Findings:

- **medium**, `w01-homebox-dnf-update-available-desktop.png`: The Fedora home server has no Update button. I have to open a terminal and run `sudo dnf upgrade tailbond-server`. The page says "turn on dnf-automatic" but doesn't show whether it's on now or how to turn it on. **Suggestion:** Show the dnf-automatic state ("dnf-automatic: off" / "on, runs daily at 06:00"). Add the enable command with a Copy button next to the upgrade command.
- **medium**, `w01-homebox-dnf-update-available-desktop.png` / `w02-updated-devices-out-of-date-backups-desktop.png`: "last update: 0.2.0, Nov 3, 03:06, worked" appears on a server set to "Tell me", with no Automatic option. Something updated it at 3 a.m., and the page doesn't say what. **Suggestion:** Say who did it: "updated by dnf-automatic" or "updated by `dnf upgrade`".
- **medium**, `w09-vps-check-failed-desktop.png`: The VPS shows a green "Up to date" chip and headline while the last check failed ("Couldn't reach GitHub"), and it runs 0.1.0. Other screens show 0.2.0 is out, so the green signal is false. The phone gets this right with "Couldn't check for updates" in red (`12-updates-check-failed.png`). **Suggestion:** Use a "Couldn't check" chip and headline, and show when the last successful check was.
- **medium**, `w03-vps-update-available-desktop.png`, `w08-vps-rolled-back-desktop.png`, `w09-…`, `w13-vps-updates-off-desktop.png`, `w02-…`, `s01-flint-devices-out-of-date-desktop.png`: Device versions are hard to see. On the VPS, "All 3 devices are on 0.1.0 or newer" lists no versions, so I can't tell who is behind the latest release. On homebox, "2 devices out of date" leaves out beryl (offline), and its version is never shown. **Suggestion:** Always list every device with its version, and compare against the latest release, not this server's version. Show offline devices too: "beryl: off, last seen on 0.1.0".
- **medium**, `s01-flint-devices-out-of-date-desktop.png` / `w01-…`: The home server knows slate7 is out of date but can't update it. I have to log in to each router's GL panel, find VPN → tailbond, and scroll to the bottom. Peplink InControl updates the whole fleet from one place. **Suggestion:** Add an "Update slate7" action on the home server, or at least a link that opens that router's tailbond page.
- **medium**, `11-updates-available.png` / `10-updates-up-to-date.png`: The phone has no Automatic option. Updating by hand means the browser downloads an APK and I allow "install from browser". Automatic means installing a separate app, Obtainium, and typing in a GitHub address. Speedify just updates from the Play Store. **Suggestion:** Ship through Play Store or F-Droid. If that's not possible, add a one-tap "Add to Obtainium" link and a one-tap in-app install instead of the browser.
- **medium**, `r05-router-automatic-desktop.png`: Automatic "installs a new version by itself" with no time window. A restart can drop devices in the middle of a call, and nothing shows when the next install will happen. Peplink lets you schedule firmware. **Suggestion:** Add an install window (for example 03:00–05:00, the default) and show "next check / install at …".
- **medium**, `r04-router-rolled-back-desktop.png` / `w08-vps-rolled-back-desktop.png`: Right after 0.2.0 failed and was undone, the same 0.2.0 is offered again with a primary "Update now" button. Nothing says whether Automatic will retry it tonight. **Suggestion:** Add "Skip 0.2.0" and say "won't retry automatically". Make the retry a secondary button and link to logs or a way to report the failure.
- **medium**, `r02-router-update-available-desktop.png` / `02-settings-update-available-row.png`: The update notice sits at the very bottom of a long page, below Tailnet machines on the router and at the end of Settings on the phone. The top status card says nothing, and the GL panel has no badge (the web dashboard has a tab badge). With "Tell me", the update only gets installed if I notice it. **Suggestion:** Put "Update available: 0.2.0" in the top status card, or add a badge on the router page and the phone's main screen.
- **low**, `r02-…` / `r01-…` / `11-updates-available.png`: Version strings don't match. The card says "0.1.0" while the footer says "tailbond 0.1.0-r42" and later "0.2.0-r1". The phone mixes "v0.2.0" with "0.1.0". **Suggestion:** Use one format everywhere. Show the build suffix only in an "About" detail.
- **low**, `r07-router-update-confirm-desktop.png` / `w04-vps-update-confirm-desktop.png`: The confirmation says devices "drop for a few seconds". On r02 the kill switch is on, so devices are blocked during the restart. It also doesn't say whether a backup is taken first. **Suggestion:** Add "A backup is saved first" (if true) and mention the kill switch.
- **low**, `19-updates-debug-build.png`: The big "Download update" button is still shown even though the text below it says Android won't install that APK over this build. **Suggestion:** Hide the button on debug builds and make "How to switch to the release build" the main action.
- **low**, `w01-…` / `w02-…`: The tab badge reads "3" on one screen and "2" on another, with no explanation of what it counts. **Suggestion:** Use a dot, or explain the count in a tooltip ("1 update, 2 devices behind").

## Task 2: Move the home server to a new machine using a backup

**Done?** Partly. Making the backup (w05) and restoring it (w06, w07) both work. Afterwards, though, I have to set the public address by hand, guess which devices need a new link, and make sure the old server is off. The page also never tells me the old server should be off. Screens: w02, w03, w05, w06, w07, w10, w11, w12, s01, r10, r11, r13, 01, 30, 31b, 34, 37.

Findings:

- **high**, `w06-restore-preview-new-vps-desktop.png`: Restoring on the new VPS writes the old machine's public address (203.0.113.9) and port 8443 onto it. The fix-up is mine: "After restoring, set the new public address (Devices tab)". Even then, devices only "pick it up by themselves within a few hours". That's hours of outage plus a manual step that's easy to miss. A Peplink restore on new hardware just works. **Suggestion:** When the backup comes from a different machine, offer "Use this machine's address (198.51.100.20)" and check it by default. Push the new address to devices over Tailscale right away and give a real time ("within a minute").
- **high**, `w10-vps-new-machine-desktop.png`: The "new machine, before restore" looks exactly like a live server. It shows Connected, 5 days uptime, 7.5 GB of traffic, "All 3 devices are on 0.2.0 or newer", and six saved backups from "this server", slate7 and beryl. I can't tell whether I'm on the new box or the old one, so I could restore onto the wrong machine or skip the restore. **Suggestion:** A fresh install should say so: "No devices yet. Moving an existing home server here? Restore its backup", with Restore as the main button. Show no device list or saved backups until there is real data.
- **medium**, `w06-restore-preview-new-vps-desktop.png`: There's no warning to turn off the old server. The router restore has one (`r10-router-restore-preview-desktop.png`: "if the old one still runs, turn tailbond off there first"). Two servers with the same keys and devices will fight. **Suggestion:** Add the same bullet to the server restore preview.
- **medium**, `w06-…` / `01-settings-updates-and-backup-rows.png`: The warning says devices "paired with a link" need a new link, but doesn't say which of slate7, pixel-8 and beryl that means. The phone's settings show nothing about the server having moved. It still says "Reached at home.example.net:443" next to an unexplained "Pair again". **Suggestion:** List each device with what it needs ("slate7: nothing; pixel-8: send a new link"). Show a banner on the phone when its server's address has changed.
- **medium**, `w07-restore-done-desktop.png`: The "Restored" dialog drops the follow-up steps (set the public address, send new links). Once I click Done, they're gone. **Suggestion:** Keep a "Finish moving" checklist on the Updates & backup tab until each step is done.
- **medium**, `w06-…`: The tunnel port changes from 443 to 8443, with no reminder that the new machine's firewall and the provider's firewall must allow it. **Suggestion:** Mention the port in the warnings, and run the port check from Setup health right after restore.
- **medium**, `w02-updated-devices-out-of-date-backups-desktop.png` / `w03-…`: The server keeps its automatic backups "on this server", which is the machine I'm replacing. Routers send their copy to homebox, but the server has no off-machine option. All I get is "Keep a copy somewhere other than this machine too". **Suggestion:** Offer an off-machine target for the server's own backups (another device, a download reminder, cloud storage). Warn when the only copies live on the server itself.
- **medium**, `30-backup-page.png` / `w02-…`: The phone says "Send a backup to homebox, homebox keeps the last 3", but homebox's Saved backups list has no pixel-8 entries. I can't tell whether phone backups exist on homebox or whether they move with the server. **Suggestion:** List phone backups in Saved backups, and say in the server backup dialog whether device backups are included.
- **medium**, `w06-…`, `w07-…`, `r10-…`, `r11-…`: File names and dates disagree. "vps-2026-11-01T0300.tbbackup" says "made Nov 2, 16:00". "slate7-2026-11-01.tbbackup" says "made Nov 2, 17:00". "before-restore-2026-11-02T2201" was created when the panel says today is Nov 3. With several backups listed, picking the right one becomes guesswork. **Suggestion:** Make the file name match the "made" time, and show the full date with time zone in the preview.
- **low**, `w12-whats-inside-desktop.png` / `r13-router-whats-inside-desktop.png` / `r10-…`: The backup summaries use internal words: "Mode: speed", "Updates: notify", "auto → notify", "Router settings (UCI)". Everywhere else the screens say "Fastest", "Tell me" and "Automatic". **Suggestion:** Use the same labels as the settings themselves.
- **low**, `w07-restore-done-desktop.png` / `r11-router-restore-done-desktop.png`: Undoing is only possible by knowing a file name. The phone has an "Undo restore" button. **Suggestion:** Add "Undo restore" to the web and GL done dialogs and keep it on the tab for a while.
- **low**, `37-restore-a-server-backup.png`: "Restore it there" doesn't say where. **Suggestion:** Say "Open homebox's dashboard → Updates & backup → Restore from a backup."

## Task 3: The router got a GL firmware update. Is tailbond still there?

**Done?** Yes, but only after scrolling to the bottom of the page. `r06` says the firmware update removed tailbond and it reinstalled itself with my settings, with nothing for me to do. Screens: r06, r01, r08.

Findings:

- **medium**, `r06-router-reinstalled-after-firmware-upgrade-desktop.png`: The one message I need after a firmware upgrade sits inside the Updates card at the very bottom. The top card just shows "Connected to homebox", the same as any other day. **Suggestion:** After a reinstall, show a one-time notice in the top status card: "Reinstalled after GL firmware update, settings kept."
- **low**, `r06-…`: Nothing says where the reinstall came from or what I'd see if it couldn't happen, for example with no internet at a hotel right after the upgrade. Peplink keeps config across firmware updates without needing a download. **Suggestion:** Add one line: "If this ever fails, restore from the copy on homebox (Backup & restore)."
- **low**, `r06-…`: The page says "Now on 0.2.0, since Nov 3, 21:36", but "Checked 2 h ago" is from before the reinstall, and the "last update … worked" line has disappeared. **Suggestion:** Run a check right after the reinstall and keep the last-update line.
